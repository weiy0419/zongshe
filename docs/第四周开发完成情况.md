## 4. 未完成风险点

1. **申贷调用时序：** `LoanApplicationServiceImpl.submitApplication` 保存申请后、当前事务提交前同步 HTTP 调 assess。风控服务从数据库读取申请，可能因事务尚未提交而查不到记录。
2. **申贷去重未触发：** 现有信贷请求只发送 `applicationId` 和 `enabledModels`，没有发送 `productId`。新接口因此明确返回 `MISSING_PRODUCT_ID` 并跳过去重。
3. **鉴权待联调：** `/api/**` 要求认证；申贷端 `RestTemplate` 调用代码中未见显式携带 JWT，需要检查是否有统一拦截器或其他鉴权配置。
4. **决策未完整回写：** 信贷成功分支未将 `decision`、`reasonSummary` 写回申请，并从 DTO 读取不存在的 `passed` 字段。申请进度页闭环不能据此视为完成。
5. **报告未持久化：** 新 assess 返回 `reportId=null`，既有报告查询和自动评估接口仍连接旧评估链，不能查询本次新结果或作为第四周持久化验收证据。
6. **策略失败默认值：** 当前策略 GET 失败会与 assess 一起进入异常分支并设置 `RISK_PENDING`；第四周允许无策略时默认使用 `WOE`，当前提交链未验证这一降级路径。
7. **WOE 与综设 II 阈值对照：** 配置阈值保持 40，未见降低；但没有用综设 II 的代表样本做旧卡/新卡对照，需由团队确认“通过阈值不低于 II”的演示口径。
8. **报告契约核对：** 外部、行为分在第四周应标记未就绪；需用实际 Web 报告页确认字段消费及申请卡明细显示。当前专项测试主要验证后端 DTO。
